# 기법 채굴·이식 (technique-transfer)

## 이 스킬이 하는 일

```
원문(남의 글/책)  ──분석──▶  기법 프로파일  ──적용──▶  내 글 (기법 이식본)
                                  │
                     내 글 ──대조──┘  (빠진 기법 진단)
```

분류 체계는 `references/technique-taxonomy.md`에 있다. **10개 영역 97개 기법**이며, 항목마다 `탐지 신호`와 `적용 지시`가 쌍으로 달려 있다. 이 파일이 단일 진실 원천이다. 여기 없는 기법을 즉석에서 지어내지 않는다. 새 패턴을 발견하면 프로파일에 `[미분류]`로 적고 사용자에게 분류 체계 승격을 제안한다.

`references/metrics.py`는 분류 체계에서 ◆ 표시된 항목을 숫자로 계산한다. **분석 전에 반드시 실행한다.** 인상 비평을 막는 닻이다.

---

## 철칙

**하나. 내용을 옮기지 않는다.**
이식하는 것은 기법이지 내용이 아니다. 원문의 사건·인물·수치·비유 소재를 사용자 글에 넣지 않는다. 구조만 가져온다.

**둘. 문장을 복제하지 않는다.**
원문 문장을 그대로 쓰지 않는다. "긴 문장 뒤에 5자 문장을 놓는다"는 가져오고, 그 5자 문장 자체는 사용자 재료로 새로 짓는다.

**셋. 한 번에 3~5개만 이식한다.**
97개를 한꺼번에 적용하면 원문도 내 글도 아닌 것이 된다. 우선순위대로 소수만.

**넷. 장르를 넘지 않는다.**
소설 기법을 보고서에 이식하지 않는다. 장르가 다르면 경고하고, 옮길 수 있는 항목만 추린다.

**다섯. 핵심 등급은 12개까지.**
전부 핵심이면 아무것도 핵심이 아니다.

## Phase 0 — 모드 결정

시작 시 다음 한 줄을 출력한다.

```
technique-transfer — {분석|대조|적용} 모드 / 원문 {N}자 · 장르 {…}
```

### 라우팅 확인

| 입력 | 보낼 곳 |
|---|---|
| AI 초안 + 내 수정본 **쌍** | `my-writing-master-prompt` |
| 고칠 내 글 하나만 (본보기 없음) | `toego-korean` |
| AI가 쓴 글의 AI 티 제거 | `humanize-korean` |
| 특정 저자(고도원·은유·유선경) 코칭 재현 | 해당 전용 스킬 |

### 모드 판정

- 원문만 주어짐 → **분석**
- 프로파일(또는 원문) + 내 글이 함께 주어지고 "뭐가 다른지" 물음 → **대조**
- 프로파일 + 내 글 + "적용/바꿔줘" → **적용**

### 분석 전 확인 (분석 모드에서만, 최대 2개)

1. **이 글의 장르는 무엇입니까?** (에세이·칼럼·소설·보고서·설교·논문 — 판정 기준이 달라진다)
2. **책 전체입니까, 일부입니까?** 책이면 아래 §표본 규칙을 따른다.

---

## §표본 규칙 (책·장편일 때)

전체를 다 읽지 않는다. 다음 세 곳을 뽑는다.

| 표본 | 위치 | 왜 |
|---|---|---|
| 도입부 | 첫 장 전체 또는 앞 3,000자 | L10(시작), L5(시점 설정)이 여기서 결정된다 |
| 중간부 | 전체의 45~55% 지점 3,000자 | 저자의 평상시 문체. 가장 대표성이 높다 |
| 절정·마무리 | 마지막 장 또는 끝 3,000자 | L8(리듬), L10(마무리)이 여기서 드러난다 |

세 표본의 측정값이 크게 어긋나면 그 자체가 발견이다. **문체가 구간마다 바뀌는 것도 기법이다**(L4-07 나선형, L9-07 정서 온도 변화). 프로파일에 기록한다.

## 분석 모드

### 1단계 — 측정 (건너뛰지 말 것)

원문을 파일로 저장하고 실행한다.

```bash
python references/metrics.py <원문파일>
```

숫자를 먼저 본다. 인상으로 시작하면 "문장이 간결하다" 같은 쓸모없는 결론이 나온다.

### 2단계 — 영역별 훑기

`technique-taxonomy.md`의 10개 영역을 **순서대로** 훑는다. 영역을 건너뛰지 않는다. 각 항목에 네 등급 중 하나를 매긴다.

| 등급 | 기준 |
|---|---|
| **핵심** | 이 기법을 빼면 다른 글이 됨. 최대 12개 |
| **사용** | 쓰이지만 결정적이지 않음 |
| **부재** | 안 쓰임. **의도적 회피로 보이면 그것도 기법이다** |
| **해당없음** | 장르상 적용 불가. 기재하지 않음 |

부재를 가볍게 보지 않는다. 느낌표를 한 번도 쓰지 않은 것은 절제라는 기법이다.

### 3단계 — 근거 붙이기

**핵심 등급에는 원문 예시 2개, 사용 등급에는 1개를 반드시 붙인다.** 예시 없는 판정은 인상이지 분석이 아니다. 예시는 원문에서 그대로 인용하되 한 문장을 넘기지 않는다.

### 4단계 — 프로파일 출력

`PROFILE-{원저자또는작품명}.md`로 저장한다. 형식은 아래 §프로파일 형식.

## 대조 모드

1. 두 글을 각각 측정하고 대조한다.

```bash
python references/metrics.py <원문> --vs <내글>
```

`←차이 큼`으로 표시된 항목(40% 이상 벌어진 곳)이 1차 후보다.

2. 프로파일의 **핵심** 기법만 가지고 내 글을 점검한다. 사용·부재 등급은 대조하지 않는다. 핵심만 봐도 충분하다.

3. 산출은 표 하나다.

| 기법 | 원문 | 내 글 | 격차 |
|---|---|---|---|
| L2-02 장단교차 | 18회 | 2회 | 큼 |
| L6-06 보여주기 | 판단어 4개 | 판단어 23개 | 큼 |
| L10-06 교훈 회피 | 없음 | 있음 | 큼 |

4. 격차가 큰 것 중 **가장 고치기 쉬운 것부터** 3개를 고른다. 어려운 것부터 시키면 사용자가 그만둔다.

---

## 적용 모드

### 1단계 — 우선순위 결정

분류 체계의 §적용 순서를 따른다. 구조(L4) → 시점(L5) → 처음과 끝(L10) → 문단(L3) → 문장(L2) → 어휘(L1) → 형상화·설득·정서(L6·L7·L9) → 리듬(L8).

**한 번에 3~5개.** 사용자가 지정하면 그것만.

### 2단계 — 적용 전 고지

무엇을 어떻게 바꿀지 먼저 밝히고 시작한다.

```
이번에 적용할 기법 3개
1. L4-08 장면-성찰 교차 — 성찰 문단 앞에 장면을 넣습니다
2. L2-02 장단교차 — 긴 문장 뒤에 짧은 문장을 둡니다
3. L10-06 교훈 회피 — 마지막 문단의 다짐을 지웁니다
```

### 3단계 — 이식

각 기법의 `적용 지시` 열을 그대로 실행한다.

**재료가 모자라면 멈추고 묻는다.** 예를 들어 L4-08(장면-성찰 교차)을 적용하려는데 사용자 글에 장면이 없으면, 장면을 지어내지 않는다. 이렇게 묻는다.

> 여기에 장면 하나가 필요합니다. 그때 어디에 계셨습니까? 무엇이 보이고 무슨 소리가 났습니까?

이것이 이 스킬이 대필기가 되지 않는 유일한 방어선이다.

### 4단계 — 산출

1. **적용본** — 고친 글 전문.
2. **기법별 적용 지점** — 어느 기법을 어디에 썼는지 표. 사용자가 되돌릴 수 있어야 한다.
3. **재측정** — `metrics.py`를 적용본에 다시 돌려 원문 수치에 얼마나 가까워졌는지 보인다.
4. **다음 회차 제안** — 이번에 못 한 기법 중 다음에 할 3개.

## §프로파일 형식

```markdown
# 기법 프로파일 — {작품·저자}

- 분석일 / 장르 / 표본 위치와 분량
- 한 줄 요약: 이 글을 이 글답게 만드는 것은 무엇인가

## 측정값
metrics.py 출력에서 특징적인 수치만 (전부 옮기지 않는다)

## 핵심 기법 (최대 12)
### L{n}-{nn} {기법명}
- **탐지 근거**: 무엇을 보고 판정했는가 (수치 또는 관찰)
- **원문 예시**: "…" / "…"   ← 2개
- **적용 지시**: 내 글에 옮길 때 내릴 명령
- **난이도**: 쉬움 / 보통 / 어려움

## 사용 기법
표 한 개. ID · 기법명 · 예시 1개.

## 의도적 부재
쓰지 않은 것 중 그 자체가 기법인 항목.

## 이식 불가 항목
장르·소재상 옮길 수 없는 것과 그 이유. 솔직하게 적는다.

## [미분류] 발견 패턴
분류 체계에 없는데 눈에 띈 것. 승격 후보.
```

프로파일은 스킬 폴더의 `profiles/`에 쌓는다. 여러 프로파일이 쌓이면 사용자가 여러 문체를 골라 쓸 수 있다.

---

## 하지 않는 것

- **전체 복사.** 원문을 통째로 흉내 내지 않는다. 기법 목록만 옮긴다.
- **저작권 침해.** 원문 인용은 판정 근거로 한 문장씩만. 프로파일에 원문을 길게 옮겨 두지 않는다.
- **97개 전부 나열.** 프로파일에 해당없음 항목을 적지 않는다. 읽히지 않는 문서가 된다.
- **점수·등급 매기기.** 원문에 별점을 주지 않는다. 좋고 나쁨이 아니라 무엇을 쓰는가만 판정한다.
- **측정 생략.** metrics.py를 돌리지 않고 분석하지 않는다.
- **재료 창작.** 사용자 글에 없는 사실·장면·감정을 지어내지 않는다. 질문으로 돌려준다.

## 파일

```
technique-transfer/
├─ SKILL.md
├─ references/
│   ├─ technique-taxonomy.md   ← SSOT. 10영역 97기법
│   └─ metrics.py              ← ◆ 항목 수치 계산
└─ profiles/                   ← 분석 결과 축적
```

## 다른 스킬과의 관계

| 스킬 | 입력 | 출력 | 방향 |
|---|---|---|---|
| `my-writing-master-prompt` | 내 수정본 쌍 | 내 문체 규칙 | 나 → 나 |
| **`technique-transfer`** | **남의 완성작** | **기법 프로파일** | **남 → 나** |
| `toego-korean` | 내 글 하나 | 고친 글 | 나 → 나 |
| `humanize-korean` | AI가 쓴 글 | 사람 같은 글 | AI → 사람 |

`technique-transfer`의 프로파일은 `my-writing-master-prompt`의 `MASTER-PROMPT.md`에 항목을 넘길 수 있다. 남에게서 배운 기법이 내 규칙으로 정착하는 경로다.
