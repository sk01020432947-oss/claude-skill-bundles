| effort | 일한 시간 | 전체 경과 | 서브에이전트 | 토큰(medium=1) | 품질/10 | 작업 방식 |

## 결정표

| 상황 | 시작 effort | 이유 |
|---|---|---|
| 평소 작업, 초안, 반복 수정 | medium | low와 토큰 거의 같고 품질 차이 큼 |
| 마감 급함 + 소리·전환 타이밍 중요 | high | 30분 이내, 프레임표 공유로 싱크 최고 |
| 대표작·쇼릴·행사 메인 영상 | xhigh | max와 품질 동급, 시간 1/3·토큰 2/3 |
| max | 거의 안 씀 | 공식 문서도 수익 체감·과잉 사고 경고. 길게 돌수록 정지 위험 |

## effort와 상관없이 프롬프트로 끌어올 수 있는 것

- high의 강점(프레임표) → medium에도 "먼저 프레임 번호별 등장 요소 표를 만들고, 영상과 소리 모두 그 표만 기준으로 짜라"를 넣는다.
- xhigh의 강점(디렉터형) → "장면별로 서브에이전트에 나누고, 받은 장면은 컨택트 시트로 검수해 반려 사유를 적어 돌려보내라"를 넣는다.
- max의 강점(꼼꼼한 마감) → "전환부 ±0.5초만 따로 뽑아 확인, 최종 압축 후 라우드니스(-16 LUFS, 트루피크 -1 dBTP)와 클리핑 재확인"을 체크리스트로 준다.
- 모델이 못 하는 확인(청취·모바일 체감)은 "미확인"으로 따로 표시하게 한다.

## 직접 비교 실험 프로토콜

1. 같은 프롬프트, 같은 모델, **세션별 별도 폴더**(한 폴더 공유 시 low·medium이 파일 정리에 2분 허비).
2. 기록: 일한 시간, 전체 경과, 서브에이전트 수, 총 토큰, 사람에게 한 질문.
3. 객관 항목 먼저: 사실 정확성(연도·숫자), 장면 전환↔소리 오차(ms), 라우드니스 폭, 한글 깨짐.
4. 주관 8항목(아이디어·완성도·움직임·한글·소리·기술·내용·지시 준수) 10점.
5. 단계당 최소 2회 돌려야 운 요소가 빠진다.
